Uniform Resource Identifiers (URIs) and URLs are the addressing protocol of the World Wide Web. However, because URLs must travel through different operating systems, email clients, routing proxies, and network hardware, they are restricted to a narrow set of safe ASCII characters.

When a URL contains international Unicode characters (like `café` or `北京`), spaces, or punctuation symbols that conflict with URL delimiter syntax (like `?`, `&`, `=`, or `#`), those characters must be translated into a standardized format known as **percent-encoding** or **URL encoding**.

## The Architecture of RFC 3986 Percent-Encoding

The Uniform Resource Identifier standard (RFC 3986) establishes strict guidelines for character classification within web addresses:

### 1. Unreserved Characters (Never Encoded)
These characters have no syntactic delimiter role in a URL and must never be altered:
- Letters: `A-Z`, `a-z`
- Digits: `0-9`
- Safe symbols: `-` (hyphen), `_` (underscore), `.` (period), and `~` (tilde)

### 2. Reserved Characters (Syntactic Delimiters)
These characters define the boundaries of different parts of a URI (schemes, hostnames, ports, paths, queries, and fragments):
- Delimiters: `:`, `/`, `?`, `#`, `[`, `]`, `@`
- Sub-delimiters: `!`, `$`, `&`, `'`, `(`, `)`, `*`, `+`, `,`, `;`, `=`

If a reserved character is used for its literal data value rather than as a URL delimiter—such as passing a user password containing `&` or an address containing `/` inside a query parameter—it must be percent-encoded.

## How Percent-Encoding Works

To encode a character:
1. Determine the byte representation of the character in UTF-8 encoding.
2. Express each byte as a pair of hexadecimal digits (values from `00` to `FF`).
3. Prepend a percent sign (`%`) before each hexadecimal pair.

```text
Character: Space (ASCII 32 / Hex 20)
Result: %20

Character: Ampersand '&' (ASCII 38 / Hex 26)
Result: %26

Character: Forward Slash '/' (ASCII 47 / Hex 2F)
Result: %2F

Character: Euro Symbol '€' (UTF-8 Bytes: E2 82 AC)
Result: %E2%82%AC
```

## `encodeURI` vs `encodeURIComponent`: Critical Differences

One of the most common web engineering bugs occurs when developers use the wrong JavaScript URL encoding method:

```javascript
const base = "https://example.com/search";
const param = "Rock & Roll / 100%";

// WRONG: encodeURI preserves '&', '/', and '%'
const badUrl = `${base}?query=${encodeURI(param)}`;
// Output: https://example.com/search?query=Rock%20&%20Roll%20/%20100%25
// Result: Server sees two parameters: 'query=Rock' and 'Roll / 100%'!

// CORRECT: encodeURIComponent encodes '&', '/', and '%'
const goodUrl = `${base}?query=${encodeURIComponent(param)}`;
// Output: https://example.com/search?query=Rock%20%26%20Roll%20%2F%20100%25
// Result: Server cleanly decodes param as "Rock & Roll / 100%"
```

| Character | `encodeURI` | `encodeURIComponent` |
| :--- | :--- | :--- |
| `:` (colon) | `:` (preserved) | `%3A` (encoded) |
| `/` (slash) | `/` (preserved) | `%2F` (encoded) |
| `?` (question mark) | `?` (preserved) | `%3F` (encoded) |
| `&` (ampersand) | `&` (preserved) | `%26` (encoded) |
| `=` (equals) | `=` (preserved) | `%3D` (encoded) |
| `+` (plus) | `+` (preserved) | `%2B` (encoded) |
| ` ` (space) | `%20` | `%20` |

Use `encodeURI()` only when you have a complete, fully formed URL path and want to ensure foreign accents or spaces are valid. Use `encodeURIComponent()` whenever you are encoding individual query values or dynamic path segments.
