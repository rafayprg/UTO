A ZIP archive turns dozens of disparate documents, assets, or datasets into a single portable container. However, opening an unfamiliar archive downloaded from the web carries hidden security and operational risks: deeply nested directories, corrupted file tables, malicious path traversals (`Zip-Slip`), or malicious decompression bombs designed to exhaust system memory.

The [ZIP Extractor & Creator](/tools/dev/zip-tool/) provides a sandbox to inspect, extract, and bundle archives directly in your browser. Because execution runs inside an isolated Web Worker thread, you can audit the contents of an unknown archive before committing files to your permanent hard drive.

## Comparing Archive Extraction Architectures

Understanding how browser-native extraction differs from traditional cloud services and native desktop software:

| :--- | :--- | :--- | :--- |
| **Privacy / Transmission** | 0 KB uploaded (100% Local) | Entire archive uploaded to cloud | Local execution |

| **Resource Safety** | Hard limits (25 MB / 100 MB) | May time out or throttle | Can lock up RAM on zip bombs |

| **File Format Support** | Standard ZIP (Deflate/Store) | ZIP, RAR, 7z, TAR | All known archive algorithms |

## Safely inspecting an archive before extraction

When you receive a bundle from an external client or download an unfamiliar open-source repository:

1. Select **Extract a ZIP** and drag your `.zip` archive into the workspace (up to 50 MB).
2. The Web Worker reads the archive's End of Central Directory (EOCD) record, walks the file headers, and renders a complete manifest of every stored file path.
3. Review directory paths (such as `reports/q3_summary.pdf` or `assets/logo.png`) before extracting.

Rather than decompressing hundreds of unneeded files onto your desktop, click the **Download** button beside only the specific file you require. The browser extracts that individual stream and saves it cleanly to your Downloads folder.

## Built-In Security Safeguards

To protect users against common archive-based exploits, Localtools enforces three strict defensive layers:

```
[ Incoming ZIP File ]
        │
        ▼
1. Header Audit  ──> Check expanded size < 25 MB/file, < 100 MB total
        │
        ▼
2. Path Sanitizer ──> Strip '../' traversals & illegal OS characters
        │
        ▼
3. Worker Stream ──> Track byte emissions in memory; abort if limit exceeded
        │
        ▼
[ Safe Extracted Download ]
```

### 1. Zip-Slip (Path Traversal) Prevention
In poorly written extractors, an archive entry named `../../../../etc/passwd` or `..\..\..\AppData\file.exe` can write files outside the intended extraction folder. Localtools strips all directory traversal sequences, flattening filenames to the base component or preventing filesystem write access entirely.

### 2. Decompression Bomb (42.zip) Mitigation
A zip bomb relies on astronomical compression ratios. A 42 KB archive can expand to 4.5 petabytes of repetitive data. Our parser audits uncompressed size headers prior to inflation and maintains a runtime byte counter during decompression. If any single file expands beyond 25 MB, or if the cumulative output exceeds 100 MB, extraction halts immediately.

### 3. Memory Isolation
All decompression algorithms execute in a separate background Web Worker. If an archive contains corrupt compression tables, the worker terminates without crashing your primary browser tab or causing system-wide freezes.

## Creating clean file bundles locally

When packaging deliverables for clients, coworkers, or tax advisors:

1. Switch to **Create a ZIP**.
2. Select your files (up to 500 files or 100 MB total).
3. If two selected files share identical filenames from different folders, the tool automatically appends numerical suffixes (e.g., `document.pdf`, `document-2.pdf`) to prevent silent data overwrites.
4. Click **Create & download ZIP**. The client-side worker archives the streams with standard Deflate compression and outputs `archive.zip`.
