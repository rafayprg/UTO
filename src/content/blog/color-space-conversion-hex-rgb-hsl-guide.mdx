Color representation is at the heart of user interface engineering, graphic design, and web accessibility. Front-end developers frequently encounter different color notations across design specifications, CSS style sheets, canvas rendering APIs, and design tokens.

Understanding the mathematical models behind **HEX**, **RGB**, and **HSL**—as well as next-generation CSS formats like **OKLCH**—allows developers to construct dynamic themes, ensure WCAG contrast compliance, and build intuitive color systems.

## The Additive Light Model: RGB and HEX

Monitors and mobile screens emit light using cathode or LED subpixels in three primary channels: **Red**, **Green**, and **Blue** (RGB). Each subpixel intensity is defined as an 8-bit unsigned integer ranging from `0` (darkness) to `255` (maximum luminosity):

```text
Pure Red:    rgb(255, 0, 0)
Pure Green:  rgb(0, 255, 0)
Pure Blue:   rgb(0, 0, 255)
Pure White:  rgb(255, 255, 255)
Pure Black:  rgb(0, 0, 0)
```

### The Mathematics of HEX Notation

Hexadecimal color codes are simply a base-16 shorthand representation of the exact same 8-bit RGB byte values:

```text
HEX: #3B82F6 (Tailwind Primary Blue)
  • Red Channel:   3B (Hex) = (3 * 16) + 11 = 59
  • Green Channel: 82 (Hex) = (8 * 16) + 2  = 130
  • Blue Channel:  F6 (Hex) = (15 * 16) + 6 = 246
  
RGB Equivalent: rgb(59, 130, 246)
```

When an 8-digit HEX code is used (`#3B82F6CC`), the final two characters specify an alpha transparency channel (`CC` in base-16 = 204 in base-10; `204 / 255 = 0.8` or 80% opacity).

## The Perceptual Model: HSL (Hue, Saturation, Lightness)

While RGB and HEX match how computer hardware displays light, they are counterintuitive for human designers. If asked to make `#3B82F6` &ldquo;a little bit darker and more muted,&rdquo; calculating the necessary adjustments to all three hex pairs requires complex mental arithmetic.

**HSL** reorganizes color into intuitive, human-centered dimensions:

1. **Hue (H):** A position on the 360-degree color circle.
   - `0°` / `360°` = Red
   - `60°` = Yellow
   - `120°` = Green
   - `180°` = Cyan
   - `240°` = Blue
   - `300°` = Magenta
2. **Saturation (S):** The intensity or purity of the color, expressed from `0%` (monochrome gray) to `100%` (vivid, full saturation).
3. **Lightness (L):** The amount of light, from `0%` (solid black) through `50%` (normal balance) to `100%` (pure white).

```css
/* Dynamic UI States with HSL */
:root {
  --btn-hue: 217;
  --btn-sat: 91%;
  
  /* Normal, Hover, and Active states adjust ONLY lightness */
  --btn-bg:         hsl(var(--btn-hue), var(--btn-sat), 60%);
  --btn-bg-hover:   hsl(var(--btn-hue), var(--btn-sat), 50%);
  --btn-bg-active:  hsl(var(--btn-hue), var(--btn-sat), 40%);
}
```

By keeping Hue and Saturation constant while varying Lightness, design systems can automate consistent button states, badges, and focus rings with zero guesswork.

## The Next Generation: OKLCH and Perceptual Uniformity

The newest standard in modern web design is **OKLCH** (Lightness, Chroma, Hue), formalized in CSS Color Module Level 4:

```css
.badge {
  background-color: oklch(0.65 0.22 250);
}
```

### Why OKLCH Outperforms HSL:
In legacy HSL, the lightness channel is mathematically uniform but **perceptually flawed**:
- `hsl(60, 100%, 50%)` (Pure Yellow) has a perceived luminance of over 90%.
- `hsl(240, 100%, 50%)` (Pure Blue) has a perceived luminance of only 15%.

Consequently, putting white text on yellow HSL fails accessibility contrast checks, while white text on blue HSL passes easily. OKLCH fixes this flaw: **65% lightness in OKLCH delivers the exact same perceived brightness regardless of whether the hue is yellow, blue, cyan, or green.**
