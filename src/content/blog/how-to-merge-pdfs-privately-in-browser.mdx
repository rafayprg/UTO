Putting several PDFs into one cohesive file sounds simple until the pages arrive in the wrong order, an appendix is missing, or a signed document behaves differently after export. A dependable merge is a structured document-preparation workflow: select the right sources, arrange their pages logically, create a new binary, and inspect what you made. 

Localtools performs the entire processing in your browser using modern WebAssembly and Web Worker technology. Because your documents do not need to be uploaded to a conversion server, confidential records like tax returns, payroll summaries, medical forms, and client NDAs remain strictly private.

## Start with a plan and keep the originals

Make a short outline before selecting files. For a professional project handover or mortgage application packet, the final document might contain:
1. A personalized cover letter
2. An executive scope summary
3. The main technical or financial report
4. Supporting receipts, schedules, and appendices

Give each source document a clear, descriptive filename before loading. When several sources are ambiguously called `scan.pdf` or `document (1).pdf`, it becomes needlessly difficult to verify the correct sequence in the organizer interface.

Keep your source originals untouched in an archival folder. Merging creates an entirely new PDF file; it should never overwrite your primary records. If you later discover an omitted addendum or need to adjust page rotations, having the clean originals means you can re-assemble without degrading image quality or extracting pages from an altered derivative.

## Select documents within browser limits

Open the PDF Merger & Page Reorder tool and choose your source PDFs. You can select multiple documents simultaneously using your operating system file picker or add extra files subsequently.

The current local engine comfortably accepts:
- Up to 25 individual PDF files
- Up to 50 MB per file
- Up to 100 MB combined batch weight
- Up to 500 total output pages

These engineered boundaries minimize the risk of mobile Safari or desktop Chrome tabs encountering out-of-memory crashes on hardware-constrained systems. If an input file is corrupted or password-protected with 256-bit AES owner security, the merger gracefully alerts you rather than transmitting the payload to an undocumented server fallback.

## Organize pages, not just files

The visual workspace represents each page with its origin filename and physical sequence number. You can organize your document through two intuitive interactions:

1. **Direct Drag-and-Drop:** Grab any page card and slide it into its desired target position.
2. **Keyboard-Accessible Indexing:** Enter the target numerical destination into the position field and press `Enter`.

Removing a page card excludes that page from the resulting compilation without altering the source file on disk. If you make a mistake, clicking **Restore all pages** brings back the complete source sequence instantly.

Consider a practical legal scenario: a two-page agreement accompanied by a three-page schedule where the final page is a countersigned signature endorsement that belongs immediately behind page 1. Your arrangement should follow:
- `Agreement.pdf` (Page 1)
- `Schedule.pdf` (Page 3 — Endorsement)
- `Agreement.pdf` (Page 2 — Terms)
- `Schedule.pdf` (Pages 1 and 2 — Body)

Visual verification of this sequence avoids costly document re-transmissions.

## Download and inspect the actual output

When you click **Merge & download**, your browser’s background Web Worker parses the cross-reference tables (XREF), merges the object streams, resolves page dictionary references, and compiles `merged.pdf`. Because execution is computationally client-side, leave the active browser tab open until the save dialog appears.

Once downloaded, open the resulting PDF in a dedicated desktop viewer (such as Adobe Acrobat, Preview, or PDF-XChange) and execute this 5-point quality audit:
- [ ] Confirm total page count matches your calculated outline.
- [ ] Inspect transitions between merged documents for consistent orientation (portrait vs. landscape).
- [ ] Verify that page scaling and print margins are uniform.
- [ ] Perform a quick text search (`Ctrl+F` or `Cmd+F`) to confirm digital text layers remain selectable.
- [ ] Check high-resolution vector logos and diagrams for fidelity preservation.

## Critical document-level limitations

While browser-native PDF merging solves 95% of everyday organizational challenges, technical operators should keep several edge cases in mind:

- **AcroForms and Fillable Fields:** If multiple input PDFs share identical form field internal names (e.g., `TextField_Name`), input conflicts can cause entries to mirror across pages. Flatten form fields prior to merging if inputs should be static.
- **Cryptographic Signatures:** Digital certificates signed via X.509 PKI seals will be invalidated if merged into a composite file. Always retain signed counterparty agreements as separate attachments.
- **True Redaction vs. Page Removal:** Excluding a page completely removes its underlying data. However, if you need to redact confidential SSNs or bank details *within* a retained page, use a certified redaction tool rather than drawing black shapes, which can leave underlying text searchable.
