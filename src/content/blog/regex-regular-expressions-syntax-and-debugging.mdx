Regular expressions (regex) are one of the most powerful and expressive string processing tools available to software engineers, data analysts, and system administrators. With a few concise pattern tokens, an engineer can validate email formats, extract transaction IDs from server logs, or sanitize user input before database entry.

However, because regex syntax is highly compact and relies on complex underlying state machines, small misconceptions about character classes, quantifiers, and engine evaluation order can produce unexpected matching bugs or catastrophic security vulnerabilities.

## Core Regex Building Blocks

Modern regex engines in JavaScript, Python, Go, and PCRE follow common syntactic conventions:

### 1. Character Classes and Shorthands
- `.` Matches any character except line breaks (unless the `s` / dotAll flag is set).
- `\d` Matches any decimal digit (`[0-9]`). `\D` matches non-digits.
- `\w` Matches any word character (`[a-zA-Z0-9_]`). `\W` matches non-word symbols.
- `\s` Matches any whitespace character (space, tab, newline). `\S` matches non-whitespace.
- `[a-z0-9]` Defines a custom character set. `[^a-z0-9]` negates the set.

### 2. Quantifiers: Greedy vs Lazy vs Possessive
Quantifiers determine how many times an element may repeat:
- `*` Matches 0 or more occurrences (greedy).
- `+` Matches 1 or more occurrences (greedy).
- `?` Matches 0 or 1 occurrence (optional).
- `{min,max}` Matches between `min` and `max` repetitions.

```text
Sample string: <div>First</div><div>Second</div>

Greedy Expression:  <div>.*</div>
Matched result:     <div>First</div><div>Second</div> (matches entire string!)

Lazy Expression:    <div>.*?</div>
Matched result:     <div>First</div> and <div>Second</div> (two separate matches)
```

By appending `?` to a quantifier (`*?` or `+?`), you instruct the engine to stop as soon as the closing token is encountered, rather than consuming to the end of the line and backtracking.

## Lookaround Assertions: Matching Without Consuming

Lookaround assertions verify context without advancing the match pointer:

- **Positive Lookahead `(?=...)`:** Asserts that the pattern follows immediately. Useful for enforcing password complexity rules:
  ```regex
  ^(?=.*[A-Z])(?=.*\d)(?=.*[!@#$%^&*]).{8,}$
  ```
  This pattern asserts at the start of the string that at least one uppercase letter, one digit, and one special symbol exist within an 8-character minimum.
- **Negative Lookahead `(?!...)`:** Asserts that the enclosed pattern does *not* follow. For example, `\b(?!un)\w+\b` matches words that do not begin with "un".
- **Lookbehind `(?<=...)` and `(?<!...)`:** Matches text only if preceded or not preceded by a specific pattern.

## Understanding & Preventing Catastrophic Backtracking (ReDoS)

The most dangerous regex anti-pattern is **catastrophic backtracking**, which powers Regular Expression Denial of Service (ReDoS) attacks.

Consider this flawed email/domain pattern:
```regex
^(a+)+$
```
If tested against `"aaaaaaaaaaaaaaaaaaaaX"`, the regex engine attempts every conceivable permutation of nesting groups before failing:
- For 10 characters: over 1,000 steps.
- For 20 characters: over 1,000,000 steps.
- For 30 characters: over 1,000,000,000 steps, pegging the CPU at 100% and completely freezing the browser tab or Node.js server.

### Golden Rules to Prevent ReDoS:
1. **Never nest quantifiers:** Avoid patterns like `(x+)*` or `(a|b+)*`.
2. **Make choices mutually exclusive:** When writing alternatives `(A|B)`, ensure that `A` and `B` cannot match the same text.
3. **Favor specific character classes over `.*`:** Instead of `.*`, use specific boundaries like `[^"\n]*` when extracting quoted strings.
